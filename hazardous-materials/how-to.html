Detailed working guide

HMIS room notes, late changes and Revit

Keep the inventory, engineering notes and quantity-change history in one portable assessment. A human places and checks the resulting text in Revit.

Jump to late quantity changes · Transfer notes to Revit · Instructions for AI

1. Start with the project record

  1. Open the Hazardous Materials Assessor. For an existing project, import its most recent JSON. Export the current browser record first if it contains work you need to keep. Imports replace the open record; they do not merge competing copies.
  2. Enter the project name, number, jurisdiction, selected assessment basis, adopted edition and reviewer. Confirm applicable amendments and other project requirements outside the automatic classification process.
  3. Collect current SDS PDFs, the owner inventory, room and control-area plans, operational descriptions, prior issued notes and supporting calculations. The browser registers SDS filenames and fingerprints. It does not embed the PDFs in JSON; retain the source package separately.
  4. For AI assistance, send the JSON, actual source documents and the linked AI workflow instructions together. Imported results require human validation, even if the incoming JSON contains reviewer names.

Existing assessment JSON remains readable. Older records start with no rooms or recorded change history. History cannot reconstruct edits made before this feature existed.

2. Confirm each inventory line

  1. Identify the product, formulation/concentration, physical state, use, location and SDS references. Create a separate inventory line for each room or distinct use condition. Split actual quantities between locations; do not repeat a whole-site quantity in every room.
  2. Select Record quantities / late change. Enter storage, closed-system use, open-system use, owner-confirmed total and unit. Provide a reason such as “Initial owner inventory” and a source with its revision/date.
  3. Leave an unknown quantity blank. Enter zero only when absence is confirmed. The owner total is independent; the app does not add the storage/use fields or convert units.
  4. Record every applicable hazard with SDS evidence, selected code edition/section, classification rationale and corroborating online database records matched to the actual material. A material with multiple hazards appears in multiple hazard sections of Excel; these are not additional stock.
  5. Resolve questions and select Validate this material when the source information is complete. Database evidence supports classification; it does not itself establish code compliance.

3. Build the room register and notes

  1. In section 3, select Add room. Enter room number/name, control area or occupancy grouping, and the intended Revit sheet/view. Each room receives a permanent internal ID. Keep that record when changing a room name or sheet.
  2. Assign every material line to a room using the inventory assignment list. Existing free-text location fields are retained; verify they agree with the room assignment. Revalidate materials after assigning them.
  3. Review the generated current-inventory block. It lists each assigned material once, with quantities, hazards and sources.
  4. Complete the room-note topics: scope, hazards, occupancy/MAQ assessment, containers/transfer, incompatibilities, containment, ventilation, signage, fire protection/alarms, and egress. Explain every not-applicable decision. AI may draft this text from supplied evidence, but the reviewer must confirm it.
  5. Add traceable references: source document/revision/page, adopted code edition/section, and calculation identifiers. Include the basis for control-area aggregation and any building-level effects. Do not treat blank MAQ table cells or “Not assessed” as a passing result.
  6. Finish all room content before final validation. Changes to any room or inventory invalidate prior room validation across the assessment. This deliberately includes rooms sharing a control area and other rooms affected by overall occupancy or protection decisions.
  7. The reviewer checks the room, shared control-area and building conclusions, checks the confirmation box and selects Validate room notes. Repeat for every room after the record is stable.

The tool does not calculate allowable quantities, occupancy, containment, ventilation, fire protection or egress compliance. Those engineering decisions and their references must be supplied and validated. Review names are workflow records, not authenticated electronic signatures.

4. Process a late quantity notice

Example: an owner changes a product from 55 gal to 110 gal. These numbers illustrate the workflow only; they do not establish an allowable limit.

  1. Export the current JSON and keep it with the previous issue. Retain the owner’s change notice and the issued Revit/PDF package.
  2. Find the affected inventory line and select Record quantities / late change. Review all four quantity fields. Change the applicable fields, confirm the unit, and identify the notice, date/revision and reason. If the new amount is not confirmed, leave it blank instead of entering an estimate as fact.
  3. Save the quantity record. The app records old/new values, source, reason, timestamp and a snapshot of the preceding assessment. The changed material loses validation. Existing narrative remains intact; current inventory blocks update and every previously validated room shows Recheck required.
  4. Inspect Quantity change history. Confirm that the previous and new values match the notice. Multiple changes retain separate records; snapshots do not contain recursively nested histories.
  5. Reassess classifications if state or concentration changes. Recheck hazard quantities across the entire control area, applicable limits and adjustments, occupancy, containment, ventilation, separation, suppression, alarms and egress as relevant. The app flags the need for review; it does not decide which safeguards must change.
  6. Revise the affected room narratives and references. Also check unchanged rooms and building-wide conclusions. Do not replace an existing engineering conclusion solely because an AI suggests new wording.
  7. Validate the changed material, then all current room notes. Reviewed export is blocked while any room is stale, incomplete or unvalidated. Draft text remains available and is labeled DRAFT — NOT FOR ISSUE.
  8. Export fresh JSON, Excel and reviewed room text. Update the Revit notes, inventory tables, schedules and plan callouts affected by the change. Archive the superseded output, identify the new issue/revision using your project procedure and verify the final PDF.

A unit change is a recorded revision, not an automatic conversion. A move to another room, revised classification or revised code basis also makes existing room approvals stale, although the dedicated old/new change history currently records quantity/unit transactions only. The JSON is editable and the history is not a tamper-proof audit log.

5. Transfer and check the Revit output

  1. Use Export draft Revit text during coordination. Use Export reviewed Revit text after every room is validated. The filename starts with the project name and identifies draft or reviewed HMIS room notes.
  2. Open the downloaded text file in a text editor. Find the room by its number and stable ID, then copy the relevant inventory and note blocks into the corresponding Revit text notes. The file includes status and reference information for checking; arrange what belongs on the issued sheet under your drawing standard.
  3. A human selects views, sheets, text types and placement. Review wrapping, clipping, symbols, legibility and references. No Revit connection, automatic model update, model-edit detection or PDF comparison is included in this version.
  4. Reconcile the inventory totals and units across Excel, text notes and plan callouts. Verify that repeated hazard rows have not been summed as extra inventory. Check all affected rooms, including those on other sheets.
  5. Export the drawing PDF and have the reviewer check it against the current JSON, change record and source notice. A reviewed text export does not certify that the Revit model or final PDF was updated.

6. Keep a recoverable handoff

  • JSON: the working record, room assignments, narrative, review metadata and quantity-change snapshots. Keep dated copies outside browser storage. Saving again may download another file with the same suggested filename; identify the latest issue explicitly.
  • Excel: hazard-based inventory and assessment worksheets. MAQ limits and compliance decisions remain “Not assessed” until separately evaluated; room-note validation does not fill these cells.
  • Text: generated room inventory and narrative for Revit placement. Existing exports do not update when the JSON changes. Replace superseded copies deliberately.
  • Source files: retain SDSs, inventory notices, plans and calculations with the handoff; the JSON contains references, not those attachments.

Use one working owner at a time. Importing another person’s JSON replaces the current record and resets review approvals. It does not merge updates or compare two branches. Recover an old issue by importing its separately archived JSON; the embedded snapshots are retained for inspection, not exposed as a one-click restore. Large histories can exceed browser storage; heed the storage warning and export JSON immediately.
