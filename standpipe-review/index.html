From technical evidence to a reviewer determination

  1. Review Basis: identify the project, reviewer, governing editions, scope and discipline-specific conditions. Save the basis. Record expected documents and revisions. These apps do not embed copyrighted code criteria or calculate automatic compliance.
  2. Review Checklist: evaluate each prompt against the actual submittal. Unknown means applicability is undecided. Not reviewed means no technical determination. Not applicable requires an explanation. Appears acceptable requires evidence. Add custom requirements for project-specific scope.
  3. Worksheet: enter the submitted condition and its governing criteria. Record a separate determination for each row. Worksheets are review records, not new calculators.
  4. Concerns and needs: save a candidate concern to keep it internal. Select Validate finding only after providing a source, citation, correction and reviewer name. Saving later edits clears module validation and requires explicit revalidation. Missing information requires an owner, milestone, requested information and reason. Deferred means explained later-phase work, not silent removal.
  5. Evidence: use the linked existing calculators, then record version, run date, result assumptions and file references. Actual PDFs and images remain outside this browser-local file.
  6. Report & Handoff: print a discipline review record or preview transfer to the Case File. Check project name and number, then confirm. A different active project must be switched in the Case File first. If no active case exists, handoff creates one from the saved basis.

Revisions: identical handoffs do not duplicate records. A changed snapshot supersedes prior checklist/document coverage from the same review instance. Prior findings, candidates and outstanding requirements remain for explicit disposition; they are never silently closed. Unchanged issues are linked rather than duplicated. Recheck and close central findings in the Case File.

Files and devices: each module stores one active review locally per browser. Export JSON for backup or transfer. Import into the matching module, or import the module JSON directly into the Case File. Case-file JSON and module JSON are different formats. No server storage or automatic sharing.

Report meaning: review coverage counts documented determinations, not acceptable design. Candidate observation text stays internal until validation. The central Case File governs final-conclusion readiness and produces the four-section disposition package. Typed identities are not authenticated signatures.
