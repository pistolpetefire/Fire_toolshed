EXIT

Travel Distance and Nearest-Exit Checker

Screening · v1.0.0Draw or import a plan with walls and obstructions, mark exits, and get the shortest real walking path from every point to the nearest exit and to the next exit if that one is blocked. Areas over your limit are shaded. Runs offline.

Screening only. Not the submittal basis. Distances are measured on a grid between cell centers and depend on the plan you draw. The applicable limit, the measurement rules and the point where travel ends come from the adopted code and the AHJ. A licensed fire protection engineer must confirm them, and the code compliance drawings remain the record.

Project and limit

Example value only. Enter the limit from the adopted code for this occupancy and sprinkler status (for example IBC Table 1017.2 or the NFPA 101 occupancy chapter, per edition), per project and AHJ.

Plan grid

Smaller cells are more accurate but slower. 2 ft (0.6 m) cells suit most floors; up to 250 × 250 cells.

Polygon input (optional)

Coordinates in the units shown, origin at the top-left, y downward. This replaces the grid drawing.

Checks and warnings

    Verification against independent Python hand calcs

    Each case runs live in this page's engine and is compared with verify_handcalc.py: exact straight-line geometry (T1, T2), an exact any-angle shortest path on a visibility graph (T3, T4), and an independent re-implementation for the example plan (T5, T6). Acceptance: within 1% (percent-of-area cases: within 1 percentage point).

    User guide

    What each input is, typical starting values, and why. Limits and measurement rules come from the adopted code; where they vary they are per project and AHJ.

    Workflow

    1. Find the travel distance limit for the occupancy and sprinkler status in the adopted code, and enter it with its citation.
    2. Set the cell size and grid size so the plan fits (columns × cell size = plan width).
    3. Draw the plan: walls and fixed obstructions (cores, shafts, fixed casework, racks), floor, and exits. Or enter the outline, obstructions and exits as a polygon and build the grid.
    4. Read the shading for the nearest exit, then switch to "if the nearest exit is blocked".
    5. Probe the worst points to see the paths. Check that each path is a route people can actually use.
    6. Export the project JSON, save the plan image and print the report. Confirm on the code compliance drawings.

    Reading the warnings

    • Error (red): invalid inputs, no exits, or a grid that is too large. Nothing is computed.
    • Warning (amber): areas over the limit, floor cells that cannot reach any exit, only one exit, a coarse cell size, or a missing citation.
    • Note (gray): measurement assumptions.

    Common mistakes

    • Using straight-line distance instead of the walking path.
    • Forgetting furniture, racks or casework that set the real path.
    • Cells too large, which closes narrow openings or doors.
    • Ending travel at the wrong point (for example at a door that is not an exit).
    • Ignoring common path of travel and dead-end limits, which this tool does not check.

    Method

    1 · Grid and line of sight

    The plan is a grid of floor, wall and exit cells. A straight step between two cell centers is allowed only if the segment does not pass through or touch a wall cell. Touching a wall corner counts as blocked, a conservative rule that keeps paths off wall corners.

    2 · Shortest real path

    d(cell) = min over allowed steps ( d(neighbor) + step length ), steps (dx, dy) with |dx|, |dy| ≤ 5 and no common factor

    Dijkstra's method from each exit (adjacent exit cells form one exit) gives the walking distance from every cell. The 5-cell step set allows near-any-angle paths: compared with the exact geodesic the error is under about 0.5% in open areas (see Verification). Distance runs from the cell center to the exit cell center.

    3 · Nearest and blocked-exit distance

    Nearest = smallest distance over all exits. If the nearest exit is blocked = the smallest distance over the remaining exits. Cells over the limit are shaded.

    Limits

    • 2D only: no stairs, ramps or travel within exit stairs; multi-level travel must be added by hand per the code.
    • Grid resolution: walls and doors snap to cells; results are accurate to about half a cell plus the step error.
    • Does not check common path of travel, dead ends, exit separation, egress width or capacity.
    • The user sets where travel ends; the tool does not judge which doors are exits.
    • Screening only. Not the submittal basis.
